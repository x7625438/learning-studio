## 二、AI Prompt 模板

### 2.1 P0-3 即时问答 · 追问链

**System Prompt**：
```
你是学生的学习助手，专注于数学、物理、化学等理科题目的讲解。
你的任务不是直接给答案，而是通过追问引导学生自己思考，找到解题思路。
遵循以下原则：
1. 先判断题目类型（计算/证明/概念/应用）
2. 从学生已知的知识出发，引导到解题关键
3. 每次只追问一个问题，不要一次问多个
4. 如果学生回答正确，给出肯定并引导到下一步
5. 如果学生回答错误，不要直接否定，而是给提示让学生自己纠正
6. 追问不超过5轮，超过后给出完整答案
7. 学生可以选择「看最终答案」直接跳过追问

当学生选择「看最终答案」时，给出完整解答，并提取本题涉及的知识点的JSON数组：
{"knowledge_points": ["知识点1", "知识点2"]}
```

**追问策略 Prompt 片段**：
```
题目类型判断逻辑：
- 含"证明""求证" → 证明题，追问「你想从哪里入手」
- 含"计算""求""化简" → 计算题，追问「你知道用什么方法吗」
- 含"是什么""为什么""定义" → 概念题，追问「你对这个概念的哪部分有疑问」
- 含"应用""实际" → 应用题，追问「你知道这道题在考什么知识点吗」
```

### 2.2 P0-2 薄弱点引擎 · 知识点提取

**System Prompt**：
```
给定用户的一道题目和AI的回答，提取其中涉及的知识点。
以JSON数组格式返回：
{"knowledge_points": ["知识点名称1", "知识点名称2"]}

规则：
- 只返回精确的知识点名称，不要返回模糊的描述
- 知识点名称使用标准学科术语（如"泰勒展开"而非"泰勒公式"）
- 如果AI回答中涉及多个知识点，全部返回
- 如果题目综合性强（跨章节），返回所有相关知识点
```

### 2.3 P0-1 学习档案 · 学习目标生成

**System Prompt**：
```
根据用户设定的学习目标（goal）和当前阶段（current_stage），
生成3条具体的本周学习建议。

返回JSON格式：
{
  "suggestions": [
    {"topic": "建议学习的主题", "reason": "为什么这个重要", "estimated_hours": 2},
    ...
  ]
}
```

### 2.4 P1-2 主动回忆 · 题目生成

**System Prompt**：
```
为指定知识点生成一道练习题。

要求：
- 难度适中（用户当前掌握度约50%，需要踮脚够到的难度）
- 题目不能与用户做过的题目重复（根据历史记录判断）
- 选择题需要4个选项且只有一个正确答案，干扰项要有一定的迷惑性
- 附上答案、解析、和针对该知识点的提示（用户求助时显示）

返回JSON格式：
{
  "question_id": "唯一ID",
  "knowledge_name": "知识点名称",
  "question_text": "题目内容",
  "choices": [
    {"key": "A", "text": "选项内容"},
    ...
  ],
  "correct_answer": "B",
  "hint": "提示内容",
  "explanation": "详细解释"
}
```

### 2.5 P1-3 论文翻译 · 摘要生成

**System Prompt**：
```
给定一篇英文论文的标题和全文，生成一段300字以内的中文摘要。

要求：
- 摘要应包含：研究问题、研究方法、主要结论、创新点
- 使用学术中文，避免口语化
- 重要术语首次出现时附上英文原文
- 不要添加「本文」「作者」等评论性话语

直接返回摘要文本，不要加任何前缀或说明。
```

### 2.6 P2-1 费曼学习 · AI 追问生成

**System Prompt**：
```
你是费曼学习法的引导者。用户正在尝试用自己的话解释一个概念。
你的任务是：
1. 在用户表述模糊或逻辑跳跃的地方打断
2. 用具体的追问帮助用户把不清楚的地方说清楚
3. 不要夸奖（如「很好」「很棒」），专注于深化理解
4. 如果用户解释清晰，给出肯定并转向下一个未讲解的方面

判断标准：
- 用户用了比喻：追问「这个比喻准确吗？哪里可能不准确？」
- 用户概念混淆：追问「你说的XX，和YY是一个东西吗？」
- 用户跳过关键步骤：追问「这一步是怎么得出的？」
- 用户解释完整：总结「你已经解释清楚了XX，现在来说说YY」

每次只问一个问题。
```

### 2.7 P2-3 情绪识别 · 干预消息生成

**System Prompt**：
```
根据用户的学习行为数据，生成一段温柔的关心消息。

行为数据（JSON）：
{
  "recent_activity": "最近的学习行为描述",
  "time_of_day": "时段（morning/afternoon/evening/late_night）",
  "emotion_signal": "检测到的情绪信号"
}

消息要求：
- 语气温柔，不说教，不强迫
- 具体描述你观察到了什么，不要泛泛地说「你很累」
- 给出1-2个具体建议
- 提供用户可选择的回应按钮标签（如「好的，晚安」「再坚持一下」「聊聊」）
- 总字数控制在80字以内
- 如果检测到late_night（凌晨1点后），语气要更柔和，强烈建议休息

返回JSON格式：
{
  "message": "消息内容",
  "quick_replies": [
    {"label": "按钮1文字", "action": "dismiss"},
    {"label": "按钮2文字", "action": "encourage"},
    {"label": "按钮3文字", "action": "chat"}
  ]
}
```

### 2.8 P3-4 知识图谱 · 图谱生成

**System Prompt**：
```
为「{topic}」这个知识领域生成一张学习路径图谱。

要求：
- 返回节点列表和边列表
- 节点包含：名称、层级（0=核心、1=前置、2=分支）、预估学习时长
- 边表示：前置关系（prerequisite）、包含关系（includes）、相关关系（related）
- 考虑「{current_level}」的用户当前水平，生成适合的学习顺序
- 每个节点用一句话描述「为什么需要学这个」

返回JSON格式：
{
  "nodes": [
    {"id": "node_1", "name": "节点名", "level": 0, "estimated_hours": 10, "description": "一句话描述", "parent_ids": []},
    ...
  ],
  "edges": [
    {"source_id": "node_1", "target_id": "node_2", "relation_type": "prerequisite", "reason": "因为..."},
    ...
  ]
```

## 三、WebSocket 事件总表

所有 WebSocket 连接通过 `/ws` 路径，认证方式同 HTTP API（Bearer Token in query param 或 header）。

### 3.1 事件分类

#### 档案与薄弱点（/ws/profile）

| 事件名 | 方向 | payload | 触发时机 |
|---|---|---|---|
| `profile_updated` | Server→Client | `{ weakPoints: WeakPoint[], todayStudyMinutes: number, streakDays: number }` | 任何写档案的操作完成 |
| `weak_point_created` | Server→Client | `{ weakPoint: WeakPoint }` | 新薄弱点生成 |
| `weak_point_updated` | Server→Client | `{ weakPointId: string, masteryScore: number }` | 掌握度变化 |
| `achievement_unlocked` | Server→Client | `{ achievement: Achievement }` | 解锁成就 |

#### 复习提醒（/ws/reminder）

| 事件名 | 方向 | payload | 触发时机 |
|---|---|---|---|
| `review_reminder` | Server→Client | `{ weakPointId: string, knowledgeName: string, message: string }` | 到达遗忘曲线最优复习时间 |
| `daily_practice_ready` | Server→Client | `{ targetCount: number, focusTopics: string[] }` | 每日练习任务就绪 |

#### 情绪干预（/ws/emotion）

| 事件名 | 方向 | payload | 触发时机 |
|---|---|---|---|
| `emotion_nudge` | Server→Client | `{ emotionState: string, triggerType: string, message: string, quickReplies: object[] }` | 检测到情绪信号 |
| `emotion_responded` | Server→Client | `{ action: string }` | 用户响应了情绪卡片 |

#### 学习伴侣（/ws/buddy）

| 事件名 | 方向 | payload | 触发时机 |
|---|---|---|---|
| `buddy_message` | Server→Client | `{ message: BuddyMessage }` | 伴侣发送消息 |
| `buddy_dismissed` | Client→Server | `{ date: string }` | 用户拒绝今日伴侣 |

#### 即时问答（/ws/qa）

| 事件名 | 方向 | payload | 触发时机 |
|---|---|---|---|
| `qa_stream` | Server→Client | `QAStreamEvent` | AI 逐字输出中 |
| `qa_done` | Server→Client | `{ sessionId: string, knowledgePoints: string[] }` | 追问链结束 |

#### 通用

| 事件名 | 方向 | payload | 触发时机 |
|---|---|---|---|
| `error` | Server→Client | `{ code: string, message: string }` | 任何服务器错误 |
| `ping` | Client→Server | `{}` | 心跳保活 |
| `pong` | Server→Client | `{}` | 心跳响应 |

### 3.2 客户端订阅示例

```javascript
// 前端 WebSocket 连接
const socket = io('/ws', {
  auth: { token: localStorage.getItem('auth_token') },
  transports: ['websocket']
})

// 订阅档案更新
socket.on('profile_updated', (data) => {
  useProfileStore.getState().updateFromWebSocket(data)
})

// 订阅复习提醒
socket.on('review_reminder', (data) => {
  useNotificationStore.getState().addNotification({
    type: 'info',
    message: `该复习「${data.knowledgeName}」了`,
    duration: 0  // 不自动消失
  })
})
```

## 四、组件状态设计

每个主要组件必须处理以下状态：

### 4.1 通用状态模式

```typescript
interface ComponentState<T> {
  data: T | null
  isLoading: boolean
  error: string | null
  isEmpty: boolean  // data === null && !isLoading && !error
}
```

### 4.2 各组件状态

#### ProfilePanel（档案面板）

| 状态 | 条件 | UI 表现 |
|---|---|---|
| Loading | `isLoading === true` | 骨架屏（3个占位块） |
| Empty | `!isLoading && !error && data === null` | 空档案引导页：「设置你的学习目标，开始吧」+ [设置目标] 按钮 |
| Error | `error !== null` | 红色错误提示 + [重试] 按钮 |
| Normal | `data !== null` | 正常展示档案内容 |

#### WeakPointPanel（薄弱点面板）

| 状态 | 条件 | UI 表现 |
|---|---|---|
| Loading | `isLoading === true` | 3个灰色卡片骨架 |

## 五、错误处理

### 5.1 HTTP 错误码约定

| 状态码 | 含义 | 用户可见消息 |
|---|---|---|
| 400 | 请求参数错误 | 「输入有误，请检查后重试」|
| 401 | 未登录/Token 过期 | 「请重新登录」|
| 403 | 无权限 | 「没有权限执行此操作」|
| 404 | 资源不存在 | 「内容不存在或已被删除」|
| 413 | 文件过大 | 「文件超过 50MB 限制」|
| 422 | AI 无法处理（如内容不合规）| 「内容无法处理，请更换题目或稍后重试」|
| 429 | 请求过快（限流）| 「操作太频繁，请稍后再试」|
| 500 | 服务器内部错误 | 「服务开小差了，请稍后重试」|
| 503 | AI 服务不可用 | 「AI 服务暂时不可用，请稍后重试」|

### 5.2 各功能错误处理

#### 即时问答（P0-3）

- **图片上传失败**：显示「图片上传失败，是否重试？」+ [重试] 按钮
- **图片内无文字**：提示「无法识别图片中的文字，请确保图片清晰」
- **追问链超时（超过30秒无响应）**：显示「网络不稳定，答案生成中断」+ [继续] 按钮
- **题目超出AI能力**：回复「这道题比较复杂，我需要想想……」+ 延长3秒后给出答案

#### 课件/教材对话（P1-1）

- **PDF 解析失败**：提示具体失败原因（如「PDF 加密无法解析」）+ 建议重新上传
- **AI 预分析超时（超过30秒）**：降级显示「网络慢，部分建议暂时无法生成」
- **PDF 页数超过200页**：提示「教材页数较多，是否只解析前100页作为试用？」

#### 主动回忆训练（P1-2）

- **题目获取失败**：显示「获取练习失败」+ [重试]，不影响已加载的题目
- **提交答案失败**：按钮变为红色警告 + [重新提交]，不切换到下一题
- **练习中断（页面关闭）**：下次进入时提示「上次练习中断，是否继续？」

#### 论文翻译（P1-3）

- **论文解析失败**：提示具体原因 + 引导用户尝试其他格式
- **术语查询英文单词不在论文中**：弹出「这个词不在论文的术语表中，给你一个通用解释」
- **网络中断导致翻译中断**：自动保存已翻译段落，已翻译内容正常显示

#### 情绪识别（P2-3）

- **用户关闭情绪开关后**：所有情绪检测逻辑静默跳过，不推送任何消息
- **情绪检测超时**：不推送，不报错，静默忽略

## 七、SSE 流式输出格式

### 7.1 通用 SSE 格式

所有 SSE 响应使用 `text/event-stream` content type。

每条消息格式：
```
event: <event_name>\n
data: <json_payload>\n\n
```

### 7.2 各功能 SSE 事件流

#### 即时问答（P0-3）

```
event: stream
data: {"type":"choice","content":"遇到极限问题，我们可以先从「直接代入」开始。","choices":["A. 0","B. 1","C. 无穷大","D. 无法确定"]}\n\n

event: stream
data: {"type":"text","content":"好的，你说得对。"}
\n\n

event: final
data: {"type":"final","content":"完整答案...","knowledge_points":["洛必达法则","极限计算"]}\n\n

event: done
data: {}\n\n
```

#### 费曼学习（P2-1）

```
event: stream
data: {"type":"text","content":"你说的「梯度」..."}\n\n

event: question
data: {"type":"question","question":"「梯度」和「导数」有什么区别？","order":2}\n\n

event: done
data: {}\n\n
```

### 7.3 前端 SSE 处理示例

```typescript
async function* streamQA(request: QAAskRequest) {
  const response = await fetch('/api/v1/qa/ask', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(request)
  })

  const reader = response.body!.getReader()
  const decoder = new TextDecoder()

  while (true) {
    const { done, value } = await reader.read()
    if (done) break

    const chunk = decoder.decode(value)
    const lines = chunk.split('\n')

    for (const line of lines) {
      if (!line.startsWith('data: ')) continue
      const data = JSON.parse(line.slice(6))

      if (data.type === 'choice') yield { type: 'choice', ...data }
      else if (data.type === 'text') yield { type: 'text', content: data.content }
      else if (data.type === 'final') yield { type: 'final', ...data }
    }
  }
}
```

## 八、交互日志记录规则

所有用户与 AI 的交互，在 AI 返回首个 token 后，立即写入 `interaction_logs` 表。

### 8.1 日志记录时机

| 功能 | 记录时机 | 记录内容 |
|---|---|---|
| P0-3 即时问答 | 用户发送问题后 | question, answer, extracted_knowledge |
| P1-1 课件对话 | 用户点击段落提问后 | textbook_id, page, paragraph, question |
| P1-2 主动回忆 | 用户提交练习答案后 | question_id, answer, is_correct |
| P1-3 论文翻译 | 用户点击段落提问后 | paper_id, section, question |
| P2-1 费曼学习 | 用户每次提交解释后 | session_id, explanation_text |

### 8.2 Chroma 向量化

每条 interaction_log 同时生成文本 embedding 存入 Chroma：

```python
# Chroma collection: 'interactions'
{
  "id": interaction_log.id,
  "embedding": openai_embedding(user_input),  # text-embedding 模型
  "text": user_input,  # 用于检索时显示
  "metadata": {
    "user_id": user_id,
    "source_type": source_type,
    "knowledge_points": extracted_knowledge,  # JSON array
    "created_at": created_at
  }
}
```

语义检索示例（用于「你之前问过类似的」功能）：

```python
def find_similar_interactions(user_id: str, query: str, top_k: int = 3):
    results = chroma_collection.query(
        query_texts=[query],
        where={"user_id": user_id},
        n_results=top_k
    )
    return results['documents'], results['metadatas']
```
